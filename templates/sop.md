# SOP / Runbook 模板

状态：讨论稿，尚未批准实施。空白模板，不可作为生产操作依据。填写后的内容仅存放于获准位置。组织规则见 [设计细节](../docs/design.md)。

由整理人／SOP owner 基于已有 [FF log](ff-log.md)、[事故记录](incident.md) 或既有操作文档起草，FFer 只补充原记录未覆盖的信息和使用偏差。先检索并修订已有 SOP，避免同一任务出现多份竞争版本；不要求每条日志生成 SOP。

## 身份与适用范围

| 项目 | 内容 |
|---|---|
| SOP ID / 标题 / 本版编号 | 待填写；标题描述要完成的操作任务 |
| 状态 | 草稿；后续区分待验证／复核、已审核、待复核、已退役 |
| Owner / 领域复核人 | 待确认；建议由另一位具备领域能力的人员复核 |
| 目的与预期业务结果 | 待填写，不承诺未经验证的收益 |
| 适用业务 / 系统 / 环境 / 版本 | 待确认；旧平台适用不代表新平台适用 |
| 适用现象与条件 / 不适用边界 | 待确认；症状相似不等于符合执行条件 |
| 来源记录及原文位置 / 版本 | 引用现有 FF log、RCA 或操作文档，不重复撰写事故经过 |
| 替代／被替代的 SOP 及版本（如有） | 待填写；保留历史关系 |

## 执行前提

| 项目 | 条件与核对方法 |
|---|---|
| 系统、数据及依赖状态 | 待确认；注明如何观察和核对 |
| 权限、操作窗口及既有授权要求 | 引用现行规则；SOP 审核不能代替生产操作授权 |
| 影响范围及必要准备 | 待确认；按实际操作明确备份、恢复或其他准备要求 |
| 开始前的停止／升级条件 | 待确认；前提不满足或适用性不明时按既有支持流程升级 |

## 操作步骤

从处理日志中提炼步骤时，区分已验证的通用步骤与仅在当次条件下使用的临时措施。可引用已有受控步骤的具体版本，不复制整套内容；必要参数说明用途和取值依据，不写入凭据或真实敏感数据。

| 步骤 | 操作／受控步骤引用 | 预期结果与观察方法 | 不符时的停止／升级动作 |
|---|---|---|---|
| 待编号 | 待设计 | 待确认；未知阈值不自行补齐 | 待确认 |

## 完成检查与失败恢复

| 项目 | 内容 |
|---|---|
| 业务成功判据及证据 | 待确认；明确数据、服务或业务结果的核对方法 |
| 恢复后需观察的项目与时间 | 待确认；不凭空指定观察时长 |
| 失败时回退／恢复条件及步骤 | 待设计；说明可恢复范围及限制，引用适用版本 |
| 无法回退或恢复失败时的升级路径 | 待确认角色及现有流程；保留必要现场证据 |
| 处理结果与后续事项记录位置 | 复用原 FF log／工单，只关联 SOP ID 与版本，无需另填执行报告 |

## 验证与审核（Owner／复核人维护）

本模板未验证。日志中一次成功是历史证据，不能自动证明 SOP 的适用范围；验证记录应绑定本版 SOP、环境、系统版本与实际输入条件。可引用获准的既有验证记录，不要求重复抄写。

| SOP 版本 | 环境 / 系统版本 / 输入条件 | 验证记录位置、日期及实际结果 | 偏差与未解决问题 | 验证人 / 复核人及意见 |
|---|---|---|---|---|
| 待填写 | 待填写 | 未验证 | 待填写 | 待确认 |

审核结论及适用边界：待评审。记录确认人、日期和依据，保留异议；未执行或验证未通过不能标为已审核可用。具体验证方式与发布规则仍待 D-09 确认。

## 使用反馈与持续维护

- 使用者继续在原 FF log／工单写实际结果，并关联 SOP ID、版本及偏差；本页只链接该反馈，无需另写相同内容。
- 来源修订、系统／依赖变化、实际使用失败或结果不符时，Owner 复核相关步骤与证据适用性。影响操作正确性时标记待复核，暂停作为操作依据。
- 定期复核周期：待按风险与使用频率确认。最近验证时间引用上表；长期无 Owner 或缺乏有效证据的内容需明确提示并安排处理。
- 不再适用时标记已退役，说明原因、生效日期及替代版本／支持路径；保留旧记录，不能静默删除历史依据。

| 日期 / 版本 | 反馈、来源变更或退役依据（链接） | 受影响步骤及处理结论 | Owner / 复核人 / 当前状态 |
|---|---|---|---|
| 待填写 | 待填写 | 待填写 | 待确认 |
