# FF log 记录模板

状态：讨论稿，尚未批准实施。空白模板，尚未导入真实资料；填写后的日志、摘要和关联仅存放于获准位置。组织规则见 [设计细节](../docs/design.md)。

## 如何使用：复用原日志，只补缺口

FFer 继续按现有流程响应告警／消息／电话、处理问题、写处理日志并发给值班同事。本模板是后续知识整理的索引，不要求再写一份处理报告。

- **已有日志**：提供原记录位置即可开始整理；原文已有的信息直接引用，由整理人提取并标明位置，无需 FFer 重填下表。
- **需要补充**：整理人仅就影响理解或复用的缺口向记录者确认，在“补充与纠错”中记录差异；未知可保留，不要求补齐所有字段。
- **关联与沉淀**：由整理人／领域负责人完成；没有 INC、RCA 或 SOP 时不必为填表而创建。导入与提取能力仍待设计，未实现自动处理。

## 原记录索引（整理人维护）

| 项目 | 内容 |
|---|---|
| 原日志 ID / 位置 | 引用现有记录；无 ID 时由整理人分配稳定索引，不要求 FFer 新编编号 |
| 来源版本 / 记录或修订时间 | 引用现有信息；未知保留；不能只保留会被覆盖的链接 |
| 原记录者 / 访问范围 | 沿用来源信息；缺失待确认，不扩大原有可见范围 |
| 重发、转发或修订关系 | 有则关联原记录；不能将一次重发算作新问题 |

## 原文信息映射（引用即可，不重复抄写）

若原日志已清楚表达下列内容，可仅标注对应段落／字段；摘要和提取值均须能回到原文。没有明确根因时，不从处理成功推断根因。

| 信息 | 原文位置／必要摘要 | 核对状态 |
|---|---|---|
| 告警／消息／电话反映的现象，业务与系统 | 待引用；保留原告警 ID（如有） | 待核对 |
| 告警、接手、操作及恢复时间与时区 | 待引用；原文只有部分时间时保留缺失 | 待核对 |
| 排查与处理动作、使用的 SOP 及版本（如有） | 待引用；包括原文中的无效尝试 | 待核对 |
| 实际结果、业务恢复的观察依据及未解决项 | 待引用；不以告警消失自动等同业务恢复 | 待核对 |
| 后续动作、负责人及现有工单 | 待引用；状态以原工单为准，注明查询时间 | 待核对 |

## 补充与纠错（仅有缺口或更正时填写）

无补充时留空。新增说明保留提供人、日期和依据；不得覆盖原日志或把事后判断伪装成当时记录。

若本次使用了 agent 排障建议，可在原处理日志中关联建议记录及所引用的 case / SOP 版本，说明实际采取的动作、结果与偏差；本模板只引用该段，不要求复制 agent 对话，也不将建议写成已执行动作或已确认根因。

| 缺口／原文位置 | 补充、纠错或待验证判断 | 提供人 / 日期 / 依据 | 确认状态 |
|---|---|---|---|
| 待填写（可选） | 待填写 | 待填写 | 待确认 |

## 关联与知识整理（整理人／领域负责人维护）

| 关联对象 | ID／位置及版本 | 关联依据 / 确认人及日期 |
|---|---|---|
| 同一问题的其他日志／现有问题工单 | 有则引用 | 待确认；相似症状不足以归并 |
| [事故记录](incident.md) / RCA | 有则引用，无则留空 | 不将每条日志或告警计为事故 |
| [SOP](sop.md) | 有则引用具体版本；标明使用反馈或修订建议 | 待复核；一次成功不等于可普遍复用 |
| [迁移设计候选项](modernisation-candidate.md) | 有可核实线索时关联 | 迁移判断独立评审，不写成原日志事实 |
