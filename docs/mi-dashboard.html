指标口径、样本边界与讨论事项
  • 范围：2026 年 7–9 月共 30 个虚构事故；默认展示完整的示例样本；“部分来源 / 字段缺失”和“来源未提供”用于演示不完整数据，不推断真实覆盖率。按发生日期归属月份，系统归属唯一。
  • P1 / P2 / P3 为示例分类，未映射公司正式严重级别。恢复耗时为示例事件至服务恢复的分钟数，不代表业务损失或 SLA。
  • 重复事故：由示例负责人确认属于已有故障模式；不凭名称相似自动认定。RCA 未确认的事故归入“待确认”，不补写根因。
  • 环比使用上一自然月及相同筛选条件和下钻路径；来源不完整时不计算环比。上月为零时不计算百分比；7 月没有 6 月样本，显示不可比较。
  • 整改按措施计数，与事故数量分开。逾期 = 有到期日、到期日早于 2026-09-30 且执行状态不是“已完成”；等于快照日期的到期项不算逾期。历史月份展示的是该批事故在统一快照时点的整改状态，不是历史月末状态。
  • “本期关注”为固定规则生成，未调用 LLM。指标旁的“口径”展示当前样本及缺失项；来源未提供显示“—”，完整样本下无匹配事故显示 0。整改完成不自动证明风险消除；有效性证据单独展示。
  • 待共同确认：首选管理维度、正式指标与责任人、ServiceNow / COSY 已有能力、来源完整性及权限。原型不决定新建 Web Service。
